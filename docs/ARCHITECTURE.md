# 结构与兼容性

`Launcher` 是不依赖原厂程序集的 WinForms 启动器。它读取嵌入的 ZIP，按组件包内容哈希选择版本目录，逐项检查 `bundle.sha256`，只恢复需要修复的静态文件，然后启动 Host。业务数据目录不属于校验清单。路径检查防止 ZIP 清单写到运行目录之外。

`Host` 直接引用少量原程序集，并在运行时加载原 App、主界面和原引擎。独立配置接管使用反射访问原版内部成员，因此明确限制兼容的原版本。用户和设备标识仅用于本地运行状态，不创建远程令牌或登录会话。原 WebSocket 服务进入已有 Offline 模式。

WPF 资源、插件发现、SQLite 原生库和 `Assembly.Location` 都依赖真实文件路径，因此使用内嵌 ZIP 加首次展开，不能把所有原 DLL 简单合并为一个托管程序集。

项目的 `.proj` 只包含元数据；流程和动作还在 `.flow`、`.script` 和相关子目录中。兼容旧项目必须保留这些文件的相对关系。原版解析器负责读写，新增入口不转换业务格式。

`tests/LocalVerification.cs` 只进入本机开发测试 Host。发布 Host 不包含这个文件。验证只运行自动生成的注释流程，旧业务项目检查只能在明确的 validation 副本目录中进行。

当前仍存在的兼容性边界：原版二进制不可从本仓库源码重建；外部应用接口可能随目标机器变化；不同组件版本之间未自动迁移本地配置；原版历史安全和功能缺陷没有经过全面审计。浏览器录制资源已补齐，但扩展注册、浏览器版本和外部服务需要对应环境验证。
