# GitHub 与发布流程

## 公开工程

运行 `scripts/Export-Source.ps1`。它按允许清单导出工程并拒绝 DLL、EXE、MSI、数据库、业务脚本、密钥等文件，避免把整个工作目录误当源码发布。解压源码 ZIP 后可直接作为仓库内容；不需要上传 build、artifacts、原安装或用户运行目录。

仓库中有 `.sln`、两个 `.csproj`、完整新增 C# 源码、PowerShell 构建和验证脚本、WiX MSI 定义、使用及开发文档、Git 忽略规则、GitHub Actions 工作流。工作流只在 Windows 上验证独立启动器并导出公开源码，不下载或上传原厂组件。工作流权限仅为读取仓库。

新增代码许可尚未选定，见 LICENSE.md。公开前由项目所有者决定许可；第三方组件始终保留自身权利，不适用新增代码未来选择的许可。

## 私有运行包

取得原厂组件的适用再分发许可后，再决定是否把完整 EXE/MSI 上传到 GitHub Releases。未明确许可时可发布新增工程，让持有原安装的用户在本机构建。不能把新增源码包称为“原厂全套源代码”。

## 版本更新

1. 同步 `VERSION` 与 `src/Shared/AssemblyInfo.cs`。
2. 从原安装重新运行 `Build.ps1`，不要手动修改上次 payload。
3. 执行独立启动器测试、私有 Host 验证，以及目标 Windows 上的安装、修复、卸载检查。
4. 关键旧项目用副本测试打开、嵌套编辑、保存及重开；不要执行业务流程作为打包测试。
5. 更新 CHANGELOG、验证结果与 SHA256。当前包未签名；正式大范围分发可增加受保护的代码签名流程，私钥不得入库。

MSI 固定 UpgradeCode、组件 GUID 和默认路径已纳入工程。原版安装保持独立。卸载保留用户运行数据，避免删除项目；升级不会自动清理或迁移旧版本运行目录。
